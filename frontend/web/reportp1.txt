## Gateway endpoints integrated and assumptions

- Integrated only through rewrite: POST /api/auth/login, POST /api/auth/refresh, POST /api/auth/logout.
- Current Gateway code confirms /api/auth is public and proxies auth requests; authenticated APIs are prepared to carry Authorization only through the centralized client.
- The Gateway has no CORS configuration, so components never call it cross-origin or call internal services.
- No public current-user endpoint is exposed for the shell. Role is decoded from the access-token payload solely for UX/navigation; it is never an authorization source and backend remains authoritative.
- No live Gateway integration fixture was run because no backend environment was started for this Phase 1 handoff.
